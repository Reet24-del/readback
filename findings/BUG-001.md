# BUG-001: Indian digit grouping is misread. ₹10,00,000 becomes "ten zero rupees"

| | |
|---|---|
| **Status** | Candidate, ready to report once the clips below are checked by ear. The original case (₹1,50,000) was confirmed by ear on 2026-10-17; the rest are from the verbatim transcription. |
| **Severity** | **Critical**: amounts are understated by up to 10,000× (₹1,00,000 → "ten rupees") |
| **Engine** | Voice Agent API TTS, text sent via `greeting` (spoken word for word) |
| **Voices** | Every voice tested: `anna` (en-GB), `alba` (en-US), `george` (en-US) |
| **Reproducibility** | **30 / 30** jobs (10 amounts × 3 voices). Full run on `anna`: **24 / 24** Indian-grouped amounts of a lakh or more misread (12 more amounts under a lakh were read correctly). |

## Summary
Any number written with Indian digit grouping (`X,XX,XXX`, the standard way to write amounts of a lakh and above in India) is spoken wrong. The normalizer seems to read **every group that isn't a Western thousands group as a separate number**. Only the last `XX,XXX` stays together:

- `1,50,000` → "one" + "50,000" → "**one fifty thousand**"
- `10,00,000` → "ten" + "00,000" → "**ten zero**"
- `99,99,999` → "ninety nine" + "99,999" → "**ninety nine ninety nine thousand nine hundred ninety nine**"

This doesn't depend on the voice, the currency sign or the context. The same amount written with Western commas, or with no commas, is read correctly.

## Root-cause experiment (voice `anna`)
| Input | Heard |
|---|---|
| `Your balance is ₹1,50,000.` | one fifty thousand rupees ❌ |
| `Your balance is ₹150,000.` | one hundred fifty thousand rupees ✅ |
| `Your balance is ₹150000.` | one hundred fifty thousand rupees ✅ |
| `Your balance is 1,50,000 rupees.` | one fifty thousand rupees ❌ |
| `Your balance is Rs. 10,00,000.` | Rs. ten zero ❌ |
| `The population is 1,50,000.` | one fifty thousand ❌ (not money either) |

## Every probed amount (identical across anna, alba, george unless noted)
| Written | Means | Spoken as |
|---|---|---|
| ₹1,00,000 | one lakh | "one zero rupees" (anna, george) · **"ten rupees"** (alba) |
| ₹1,50,000 | 1.5 lakh | "one fifty thousand rupees" |
| ₹8,00,000 | 8 lakh | "eight zero rupees" |
| ₹8,50,000 | 8.5 lakh | "eight fifty thousand rupees" |
| ₹10,00,000 | ten lakh | "ten zero rupees" |
| ₹14,00,000 | 14 lakh | "fourteen zero rupees" |
| ₹15,00,000 | 15 lakh | "fifteen zero rupees" |
| ₹16,50,000 | 16.5 lakh | "sixteen fifty thousand rupees" |
| ₹18,50,000 | 18.5 lakh | "eighteen fifty thousand rupees" |
| ₹99,99,999 | ~1 crore | "ninety nine ninety nine thousand nine hundred ninety nine rupees" |
| ₹3,45,67,890 | 3.46 crore | "three forty five sixty seven thousand eight hundred ninety rupees" |
| ₹73,94,88,324 | 73.9 crore | "seventy three ninety four eighty eight thousand three hundred twenty four rupees" |
| ₹28,00,60,143 | 28 crore | "twenty eight zero sixty thousand one hundred forty three rupees" |

Crore amounts are worse: the normalizer reads each comma group as its own number.

The raw results for all 30 jobs are in [BUG-001-probe-results.jsonl](BUG-001-probe-results.jsonl).

## Why it matters
- India writes every amount of a lakh and above this way: bank SMS, invoices, EMI reminders, loan approvals. A voice agent reading that text aloud tells the customer the wrong amount.
- "₹10,00,000 has been debited" spoken as "ten zero rupees" hides a ten-lakh debit, which is exactly the kind of message that has to be clear.
- AssemblyAI's TTS page promises "prices … come out exactly as written."
- The formatted transcription (Sync STT) turns the misread back into `₹1,50,000`, so a pipeline that checks TTS with formatted STT **would never notice this bug**.

## Reproduce
```bash
.venv/bin/python -m readback.smoke "Your balance is ₹10,00,000." --voice anna --no-cache
.venv/bin/python -m readback.runner --ids money-001,money-006,money-007,gen-money-007 --voices anna,alba,george
```
